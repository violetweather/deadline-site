How it works

Deadline is a closed coding benchmark. Models get one blind shot at original tasks, and hidden tests decide. No judge model. No vibes.

22

Machine-generated tasks, kept out of training data

Every task is GENERATED by a machine, not written by a human: hidden cipher pipelines to reverse-engineer (a difficulty ladder from depth 2 to depth 10), randomized state machines, binary formats with checksums, a scrambled calendar, expression evaluators with randomized precedence tables, performance gates where the obvious solution times out, and full interpreters whose semantics are partly generated. Nearly half the tasks are PURE INFERENCE: no rulebook at all, only observed behavior (machine traces, raw byte encodings, example evaluations, calendar observations, a spec with redacted semantics, example databases with the exact rows a hidden SQL report must return) from which the hidden system must be reverse-engineered. Tasks span Python and SQLite SQL. Memorized conventions are useless; only reading the actual rules works. The prompts are public (in this repo), but the test suites and reference solutions are private. Public benchmark answers leak into training data and inflate scores; Deadline's graders never leave the maintainer's machine.

Every prompt carries a canary GUID. If it ever appears in a model's unprompted output, the set has leaked and gets rotated.

→

One blind attempt, graded by fuzz-tested oracles

The model gets the task prompt and replies with code. That code runs against hidden tests in a sandbox — including fuzz oracles that compare it with a private reference on hundreds of random inputs, so near-miss solutions that survive handpicked cases still die. No retries after seeing errors, no judge model scoring style points. Brutal-tier tasks award partial credit per test group; everything else is pass or fail.

100

Scored out of 100, weighted by difficulty

Tasks are worth points by difficulty and depth, normalized so a perfect run is always 100. And every task carries a TOKEN BUDGET — its deadline: a solved task's points decay by budget÷tokens when the model blows past it. The headline DL Score is correctness times timeliness — correct but bloated loses to correct and lean.

Official runs repeat every task three times and report the mean with a ± spread, because models are random and single runs lie. A second strict score counts a task only if every attempt held up — luck doesn't survive it. Tasks the strongest models ace get retired and replaced, so the ceiling keeps moving up.

2×

Two kinds of results

OFFICIAL — the maintainer runs the model end to end through the API. Fully controlled, three attempts per task.

COMMUNITY — anyone runs the public prompts against any model and submits the raw replies. The maintainer re-grades those replies against the private tests, so a score can't be made up. The site shows only the per-model average of all verified submissions — never individual results, never usernames.

What Deadline measures — and what it does not

Deadline measures spec-exact Python 3 and SQLite SQL, standard library only, from single functions to small multi-file projects, in one blind attempt. It does NOT measure other languages, large-repo navigation, dependency wrangling, or long agentic sessions. A high Deadline score means careful reading and correct code under pressure; it is not a claim about all of software engineering.

What keeps it honest

Private tests · verified re-grading · canary GUID leak detection · sandboxed execution · global duplicate detection across all submissions · style-consistency review against other submissions of the same model · per-task receipts from the client (timings, token counts, the model name the provider echoed back) · effort-label plausibility checks · a ✓ / ✗ mark showing whether a community average is backed by more than one submission · difficulty-weighted scoring with error bars. Costs come from token counts priced by a public, auto-updated price table.

  • No judge model — style earns nothing, only passing tests count.
  • No self-reported scores — every number on the site was graded here.
  • No second chances — one blind attempt per task, per sample.
